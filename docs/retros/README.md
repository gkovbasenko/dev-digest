# docs/retros — multi-agent run retrospectives

One file per evaluated multi-agent run (typically a `/run-plan` execution), named
`YYYY-MM-DD-<feature-slug>.md`. Generated by the **`/workflow-retro`** command
(`.claude/commands/workflow-retro.md`), which parses the run's session transcript via
`.claude/scripts/workflow-retro/parse_run.py`.

## What a retro contains

- **Metrics** (deterministic, from the transcript): agent roster, parallel waves, per-agent
  wall-clock, orchestrator-side token usage, tool-call histogram.
- **Analysis** (synthesized, evidence-cited): orchestration efficiency, what helped, what was
  hard, duplicated work, what was missed.
- **Feed-forward brief**: the reusable context to hand the *next* similar run up front.
- **Proposed INSIGHTS**: durable facts the run surfaced, drafted for the user to approve into a
  module's `INSIGHTS.md`.

## Hard limitation — read before trusting the numbers

Token numbers in a retro are **orchestrator / main-thread spend only**. Per-subagent internal
token usage is **not recoverable**: subagents leave no `isSidechain` rows in the orchestrator
transcript and their `tool_result` carries no usage metadata. Per-agent cost is approximated by
**proxies** — wall-clock duration, report length, tool-call count.

## Boundary vs INSIGHTS.md

Retros hold **volatile** run data (counts, tokens, timings) — which the `engineering-insights`
skill explicitly bars from `INSIGHTS.md`. Durable, non-obvious facts a run surfaces are
**proposed** in the retro and, only on approval, committed to the relevant module's
`INSIGHTS.md`. The two files never overlap.
